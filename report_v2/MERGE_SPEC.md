# 복합공시 병합 에이전트 지침 (2026-10-20)

같은 거래·같은 회사의 같은 날 공시 여러 건을 사용자에게 **한 꼭지**로 보여 주기 위해, 이미 만들어진 공시별 보고서(`*_v2.json`)를 읽고 병합본의 **텍스트 부분만** 쓴다.
재무·가치평가·컨센서스·뉴스·참고 공시 목록·태그·중요도는 호출자(`dart_merge.py`)가 대표 공시 보고서에서 가져와 붙이므로 쓰지 않는다.

## 입력
호출 프롬프트가 `trial_case/<날짜>/merge_input_<대표접수번호>.json` 을 알려 준다. 구성원 보고서(`members[]`)가 들어 있고, 각 항목은 corp_name, stock_code, rcept_no, disclosure_title, tag, sentiment, headline, kpis, points, importance, importance_reason 등이다. `rep` 는 대표 공시(중요도·점수가 가장 높은 건)의 접수번호다.

## 쓰는 법
- **새 숫자를 만들지 않는다.** 모든 수치(금액·비율·날짜·가격)는 구성원 보고서에 이미 있는 값만 쓴다. 합산·차이·비율 같은 계산, 반올림 변경, 외부 조회(MCP·웹 검색)는 하지 않는다. 같은 값이 보고서마다 표기가 다르면(예: 3,580억 / 3,584억) 둘 다 쓰거나 대표 보고서 표기를 따르고 차이를 밝힌다.
- 한 거래로 묶인 공시는 **거래 하나의 이야기**로 쓴다(양도·양수, 임대·임차는 상대방 시점의 같은 내용이므로 합친다). 별개 사안이 함께 묶였으면(같은 회사의 다른 공시) 대표 거래를 먼저 쓰고 나머지는 포인트 한두 줄로 따로 밝힌다.
- 문체는 구성원 보고서와 같다: 바쁜 투자자용, 짧고 쉽게, 법률 용어는 풀어쓴다. "계산", "역산", "도구 이력", "시장 추정", "공시가 아님" 같은 군더더기 표기는 쓰지 않는다.
- 어느 회사 공시에서 나온 내용인지 `points[].src` 에 회사 약칭으로 적는다(예: "로템", "위아", "로템·위아"). 한 회사뿐이면 생략해도 된다.
- 투심은 **건별로 따로 판단**한다. 구성원마다 `filing_sentiments[접수번호]` 에 `{label, reason}` 을 쓰고(자기 공시 내용만 보고), 묶음 전체의 `sentiment` 는 이 건별 판단과 대표 거래의 성격을 종합해 따로 정한다. label 은 긍정적 / 부정적 / 혼재됨 / 알수 없음.

## 출력
`output` 으로 알려 준 경로에 아래 JSON 하나만 쓴다(그 밖의 파일은 만들지 않는다).
```
{
 "headline": "45자 내외, 묶음 전체를 한 줄로",
 "brief": "두 줄 이내(공백 포함 90자 이내): 무엇이(핵심 수치) + 투자자에게 의미",
 "sentiment": {"label": "...", "reason": "40자 내외 한 문장"},
 "filing_sentiments": {"<접수번호>": {"label": "...", "reason": "한 문장"}, ...},   // 구성원 전부
 "kpis": [{"label":"","value":"","sub":""}, ... 정확히 4개],
 "points": [{"type":"pos|neg|unk","text":"","src":""}, ... 6~9개],
 "importance_reason": "한 문장"
}
```
- kpis 4개: 거래 전체를 보여 주는 값으로 고른다(두 회사 값을 한 칸에 같이 써도 된다. 예: "로템 6.1% · 위아 4.6%").
- points: 긍정(pos)·부정(neg)·확인 필요(unk)를 고르게. 중복되는 내용은 합치고, 구성원 한쪽에만 있는 리스크도 빠뜨리지 않는다.
- git 명령을 쓰지 않는다. `DART_API_KEY` 등 비밀 값을 출력하지 않는다. 최종 응답은 3줄 이내.
