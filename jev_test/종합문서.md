## 0. 한눈에 보기

1. **Jev의 역할은 분류자 하나다.** 공시를 읽고 "다음 단계로 넘길지(통과) / 닫을지(탈락)"만 정한다. 요약·분석·중요도 산정은 기존 에이전트 단계가 한다.
2. **규칙 필터가 Jev 앞에 선다(기본값).** 공시명 규칙이 일주일 리스트 공시의 83%를 본문 없이 닫는다. 규칙 필터를 빼고 Jev만 쓰면 정형 서류까지 진행으로 올려 보내므로 대체할 수 없다.
3. **새 주간 검증에서 재현율은 유지됐다.** 본문 포함·영문 질문의 Noul ≥0.5가 개발 주간 96%, 검증 합계 94%(66건 중 4건 놓침). 세 질문 유형을 합친 앙상블 OR는 검증 합계 98%(1건 놓침).
4. **정밀도는 유지되지 않았다.** 개발 주간 90% → 검증 합계 65%. 개발 주간의 정밀도는 같은 표본에서 질문을 고친 결과라 낙관적이었다.
5. **불필요 통과 34건의 상당수는 Jev의 오류라기보다 규칙 해석·맥락 문제다.** 자회사 사본·부속 공시 11건, 정례 성격(금액 규칙 vs 정례 규칙 충돌) 11건, 풍문 재공시 5건, 기타 7건.
6. **사람이 정해야 할 정책 질문 12개와, 항목별 검토 126건(CSV)이 남았다.** 사람 판정이 들어오면 `apply_review.py`로 반영해 즉시 재채점한다.

## 1. 역할과 라벨

Jev는 공시 1건을 받아 아래 4가지 중 하나로 보낸다.

| 라벨 | 한글 | 의미 | 다음 동작 |
|---|---|---|---|
| `PASS` | 통과 | 본문만으로 중요 판단이 선다 | 다음 단계로 |
| `PASS_CHECK` | 통과·확인 | 진행 쪽이나 **계산**(자기자본·매출 비율, 전년 동월비) 또는 **정정 전후 대조**가 필요 | 다음 단계로 + 확인 사항 표시 — 계산은 에이전트가 한다 |
| `HOLD` | 보류 | 규칙이 충돌하거나 해석이 갈려 **사람 검토**가 필요 | 검수 큐 (기본 동작은 정책 질문 Q9) |
| `DROP` | 탈락 | 중요하지 않음 | 종료 |

"진행"은 `PASS`와 `PASS_CHECK`이다.

## 2. 공시 중요도 판단 원칙 (v0.2)

### 2-1. 현재 시스템의 규칙

**1차 — 공시명 규칙 필터** (`dart_rules.py`, 본문을 보지 않음)

- `exclude`: 투자설명서, 일괄신고추가서류, 증권발행실적보고서, IR 개최, 대량보유상황보고서, 임원·주요주주 소유상황보고서, 최대주주등 소유주식변동신고서, 주주총회 관련 전부, 채무증권 신고서, 신탁계약 관련, 의결권대리행사권유참고서류, 계열회사 거래, 결과보고서류, **정정 공시(`[기재정정]`·`[첨부정정]`) 일괄**
- `separate`: 사업보고서·반기·분기·감사보고서, 지분증권·합병·분할 증권신고서 (별도 처리, 미구현)
- `review`: 그 외 전부 → 본문을 보고 판단

**2차 — 본문 기반 판단** (`judge_rules.md`)

1. 절대 금액이 있으면 **30억 원 이상** 또는 본문에 적힌 자기자본·매출의 **1% 이상** → 중요
2. 금액이 없으면 중요한 경영 판단이거나 미래 사업에 영향을 주는 요소 → 중요
3. 정례적이고 특이하지 않은 공시는 제외
4. 주식수 변동(0.1%↑)은 DART가 아니라 KIND 크롤링으로 처리 (미구현)

보조 결정: 30억 기준을 넘는 소규모 경계 사례도 통과 · 월간 실적 공정공시는 전년 동월 대비 ±10% 이상일 때만 통과 · 지주사와 상장 자회사의 동일 공시는 상장 자회사만 처리.

### 2-2. 판단 원칙 P1~P8

| # | 원칙 |
|---|---|
| P1 | **영향의 크기** — 금액(30억 원 또는 자기자본·매출 1%) 또는 사업·지배·자본구조 변화의 규모 |
| P2 | **새로움** — 이미 알려진 사안의 재공시·종결·사본은 탈락. 단 금액이 큰 보증·대여의 연장·대환은 통과(규칙 1) |
| P3 | **정례성** — 법·제도상 반복되는 행정·거버넌스 공시는 탈락 (기준일 설정, 독립이사 정기 선임, 위원회 개최, 월간보고서 게시) |
| P4 | **방향 전환** — 결정·계약·소송 결과·중단은 통과 쪽, 절차 진행은 탈락 쪽. **임상은 예외: 계획 변경 승인이라도 통과** |
| P5 | **정보 가치** — 월간 실적은 전년 동월 ±10% 이상일 때만. 비교 계산이 필요하면 통과·확인 |
| P6 | **정정 공시** — Jev가 변경 내용으로 판정(시험 전용, 운영 미적용). 큰 변동이면 통과 |
| P7 | **놓침 비용 우선** — 경계에서는 통과 쪽, 판단이 갈리면 보류 |
| P8 | **계산은 다음 단계의 몫** — 비교 기준 계산이 필요한 건은 단순 통과가 아니라 통과·확인 |

### 2-3. 정정 공시 기준 (라벨링에 적용)

- `PASS` — 금액이 ±10% 이상 변경, 또는 해지·구조 변경
- `PASS_CHECK` — 금액 변동분이 30억 원 이상이나 10% 미만 / 계약상대·판매지역 변경 / 거래 종결·소송 제기 같은 후속(원 공시와 대조 필요)
- `HOLD` — 변경 범위가 너무 커서 판단하기 어려운 경우(예: 68만 자 증권신고서 자진정정)
- `DROP` — 오기·일정·기간·문구 정정, 금액 변동 30억 원 미만, 자회사 사본, 정형 서류(채무증권 신고서·증권발행실적·IR·정기보고서)의 정정

## 3. 파이프라인과 Jev의 위치

```
OpenDART 전체 공시 (하루 약 620건)
  └ 종목 리스트(코스피 290)            약 100건/일
      └ 공시명 규칙 필터  ← 기본값: Jev 앞       exclude 약 83% 종료
          └ review 약 17건/일
              └ (자회사 중복 제거: dart_subsidiary)
                  └ ★ Jev 분류자 ★  →  PASS / PASS_CHECK → 다음 단계(에이전트 심화 분석)
                                      HOLD               → 사람 검수 큐
                                      DROP               → 종료
```

| 단계 | 입력 | 담당 |
|---|---|---|
| 금액 환산 | 본문의 원 단위 숫자 → `(약 N억 원)` 병기 | 코드 (v1 전처리) |
| 정정 증감 계산 | 정정 전·후 숫자 쌍 → 증감률·증감액 | 코드 (v1 전처리) |
| 의미 판단 | 위 입력을 포함한 state와 질문 묶음 | **Jev** |
| 임계값·조합·라벨 결정 | Jev가 돌려준 확률 | 코드 |

## 4. 실험 설계

| 요인 | 수준 |
|---|---|
| 질문 유형 | Noul(한 덩어리) · Choice(4단계 라벨) · Score(중요도 0~4) · 원자 Noul 8~10개의 코드 조합 · 앙상블(OR / 2-of-3) |
| 입력 | T(제목+회사명) · TD(+본문 요약, 정정이면 정정 전·후 표와 증감) |
| 질문 언어 | 한국어 · 영어 (state는 한국어 그대로) |
| 전처리 | v0(원문) · v1(억 환산 + 정정 증감 계산) |
| 규칙 필터 | 선행(기본값) · 제거(시험 전용) |

- **지표**: 재현율(1순위, 놓침은 복구 불가) · 정밀도 · 놓친 건·불필요 통과 목록 · 재실행 일관성. HOLD는 진행으로 간주한 값을 기본으로 보고한다.
- **절차**: 개발 주간 9/7~9/11에서 v0 → v1로 질문을 고치고, **v1을 고정한 채 새 주간 두 곳(9/1~9/4, 9/30~10/1)에 그대로 적용**했다. 질문 수정은 문서화된 원칙(P1~P8)만을 근거로 했다.
- **정답**: 개발 주간은 4단계 재라벨(Claude 위임, 통과·확인 3건·보류 5건 포함), 검증 주간은 기존 판정의 가/부를 통과/탈락으로 옮긴 것(새 판정 없음, 통과·확인·보류 라벨 없음).
- 모델은 버전 ID `jev-1.13.0`로 고정. 요청당 입력 약 2천 토큰, 비용 약 $0.0001 — 비용은 설계 변수가 아니다.

| 파라다이스 월간 실적(전년 동월 +32.1%) | 0.21 | **입력 요약이 숫자를 잘라냄.** 표가 큰 공시에서 요약(앞 800자 + 일부 줄)에 증감률이 빠졌다. Jev의 오판이 아니라 전처리 문제 → 다음 실험 |

### 5-6. 규칙 필터 시험 (개발 주간, 필터가 닫은 382건을 제목만으로 Jev에 입력)

영문 질문 Noul ≥0.5에서 108건(28%)이 진행으로 나왔다. 특히 `최대주주등소유주식변동신고서` 34/34건, `대량보유상황보고서` 28/28건이 전부 진행이었다. 지분 변동은 KIND로 따로 처리하기로 한 대상이므로 **규칙 필터를 Jev 앞에 두는 기본값이 맞다.** 필터가 닫은 비정형 유형(임시주총 결과, 자기주식취득결과보고서, 계열회사 거래)에서 Jev가 진행으로 본 건은 CSV의 "규칙 필터 점검" 행으로 넣었다.

### 5-7. 정정 공시 (개발 주간, 시험 전용)

정형 서류 정정 11건을 유형 규칙으로 먼저 제외하고 정정 전·후 증감을 코드가 계산해 넘기면, Noul ≥0.3에서 재현율 100%(10/10), 정밀도 83%(23건). 수치가 있는 정정(신한지주 +48%, SK디스커버리 +26%, DL이앤씨 +7.2%, HJ중공업 +4.3%)은 Noul 0.80~0.96으로 잡혔다. 증감이 없는 후속 사건(거래 종결, 소송 제기)은 0.33~0.44로 낮아 임계값 0.3이 필요했다. 오류 사유가 "오류 정정"인 건(LS 교환사채 단위 오기)은 증감이 -99.9%로 계산돼 오탐이 됐다. **검증 주간에는 정정 공시에 대한 기존 판정이 없어 검증하지 못했다.**

### 5-8. 일관성 (같은 설정 재실행)

Noul 평균 차이 0.013(최대 0.08), 0.5 기준 판정이 뒤바뀐 건 2/117, Choice 선택이 뒤바뀐 건 5/117. **1~2건 차이는 잡음이다.**

## 6. 결론과 잠정 운영안

| 항목 | 잠정안 | 근거 |
|---|---|---|
| 순서 | 규칙 필터 → 자회사 중복 제거 → Jev | 5-6 |
| 입력 | 제목 + 회사명 + 본문 요약(원 단위는 억 환산) | v1 전처리 |
| 질문 언어 | 영어 | 본문 포함 Noul ≥0.5 재현율 영어가 한국어보다 높았음(검증 94 vs 88, 개발 96 vs 84) |
| 진행 판정 | **Noul ≥0.3, 또는 앙상블 OR** | 검증 합계 재현율 98%. 놓침은 66건 중 1건 |
| 검수 큐 | 확률이 0.3~0.7인 건과 `HOLD`를 사람 검토로 | Choice가 `HOLD`를 거의 고르지 않음 |
| 단독 질문 유형 | Score 단독·원자 조합 단독은 쓰지 않음 | 재현율이 낮거나 불안정 |

이 운영안은 **개발·검증 주간 합쳐 3개 구간에서의 일치도**일 뿐이며, 사람 라벨이 확정되고 새 주간으로 한 번 더 검증되기 전에는 잠정이다.

## 7. 한계

- **정답이 독립적이지 않다.** 모든 라벨이 Claude 판정에서 왔고, 개발 주간의 4단계 라벨은 같은 Claude가 다시 붙였다.
- **기간별 판정 기준이 같지 않다.** 9/1~9/4 판정은 V2 시기, 9/30~10/1은 월간 실적 ±10%·자회사 중복 규칙이 정착하기 전에 이루어졌다. 같은 유형이 기간마다 다르게 판정됐을 수 있다 (특히 B 유형).
- **표본이 작다.** 정답 진행 66건(검증), 놓침 4건이라 신뢰구간이 넓다.
- **정정 공시는 검증하지 못했다.**
- **입력 요약이 긴 표를 자른다.** 표가 큰 공시(월간 실적 등)는 요약 단계에서 핵심 숫자가 빠질 수 있다.
- 자회사 중복 제거 단계는 시험에서 재현하지 않았다.

### 8-1. 정책 질문 (12개)

각 질문에 "권고"를 붙였으나 결정은 사람의 몫이다. 답을 알려 주면 질문·라벨·코드에 반영한다.

### 8-2. 항목별 검토 파일 (`human_review_queue.csv`, 126행)

| 우선순위 | 건수 | 내용 |
|---|---:|---|
| 1 | 22 | 라벨이 `HOLD`·`PASS_CHECK`인 건, Jev가 놓친 건 |
| 2 | 44 | Claude 경계표시 + 불일치, 사본이 아닌 불필요 통과 |
| 3 | 60 | 그 외 경계표시, Jev 확률 경계(0.3~0.7), 규칙 필터 점검 |

- **채울 열**: `사람 판정(PASS/PASS_CHECK/HOLD/DROP)` (이 4가지 값만 인식, 대소문자·하이픈 무시), `사람 메모`(선택). 다른 열은 수정하지 말아 달라.
- 열 안내: `검토사유`(왜 목록에 들어왔나), `Claude 현재 라벨`·`라벨 근거`, `Jev Noul/Choice/중요도`(해당 설정의 값), `힌트`(자동 분류), `DART 링크`(원문).
- **파일을 돌려받은 뒤**: `python jev_test/apply_review.py <파일.csv>` → 사람 라벨이 정답셋을 덮어쓰고(`label_source=human`) 모든 채점 스크립트가 사람 라벨 기준으로 다시 계산된다. 원본 Claude 라벨은 `label_ai`로 남는다.
