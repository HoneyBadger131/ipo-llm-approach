> 작성 기준: 2026-10-08 · 대상: 코스피 290 종목 DART 공시 · 모델: TypeSafe `jev-1.13.0`
> 이번 판은 **사용자 1차 검토(126행)와 정책 답변 12개를 반영한 2차 판**이다. 정답 라벨은 *사람 명시 판정 + 정책 계층 + Claude 판정*이며, 점수는 "라벨과의 일치도"이지 실제 정확도의 증명이 아니다.

## 0. 한눈에 보기

1. **Jev는 분류자 하나다.** 공시를 읽고 `PASS / PASS_CHECK / HOLD / DROP`으로 보낸다. 요약·분석은 기존 에이전트 단계가 한다.
2. **정책 답변을 질문 v2b로 옮겼더니 정밀도가 크게 올랐다.** 자회사 사본을 제외한 운영 시나리오(181건, 정답 진행 106건)에서 Noul ≥0.5의 정밀도가 v1 72% → v2b 86%, 재현율은 93% → 89%.
3. **재현율 우선 운영점도 안정적이다.** Noul ≥0.2에서 재현율 98%(2건 놓침), 정밀도 74%. 구간별(개발·검증 둘)로 97~100%. 놓친 2건은 모두 사람이 `PASS`로 둔 SK하이닉스 풍문·조회공시인데, 이는 사용자 정책 Q3(풍문은 `DROP`)과 사람 라벨이 충돌하는 건이다.
4. **제안 운영 구성**: 규칙 필터 → 자회사 중복 제거 → Jev. Noul ≥0.5는 진행, **0.2~0.5는 `HOLD`(진행 + 검수 표시, 하루 약 2.8건)**, 0.2 미만은 `DROP`.
5. **규칙 필터를 조정했다**(Q12). 분쟁 리스트 10개 회사는 주총·의결권 권유·기준일·독립이사 공시를 제외하지 않고, 사람이 일관되게 `DROP`한 3개 유형을 제외에 추가했다. 기존 정답셋에서 진행 라벨 공시를 잃은 것은 0건이다.
6. **남은 일**: 2차 검토 CSV(60행)와 정책 질문 9개. 사용자 판정이 들어오면 `apply_review.py`로 반영해 바로 재채점한다.

## 1. 역할과 라벨

| 라벨 | 한글 | 의미 | 운영 동작 |
|---|---|---|---|
| `PASS` | 통과 | 본문만으로 중요 판단이 선다 | 다음 단계로 |
| `PASS_CHECK` | 통과·확인 | 진행 쪽이나 계산(비율·전년 동월비)·대조·규모 확인이 필요 | 다음 단계로 + 확인 사항 표시 — 계산은 에이전트가 한다 |
| `HOLD` | 보류 | 규칙이 충돌하거나 판단이 갈림. 알릴 가치는 있으나 심화 분석은 불필요한 사건도 사용자가 이 라벨로 표시함 | **진행시키되 검수 표시**(놓침 비용 우선). Jev의 회색지대(0.2~0.5)가 여기에 해당 |
| `DROP` | 탈락 | 중요하지 않음 | 종료 |

"진행" = `PASS`·`PASS_CHECK`·`HOLD`.

### 2-2. 기본 원칙 (v0.2에서 유지)

- **영향의 크기**(금액 30억 원 또는 자기자본·매출 1%, 사업·지배·자본구조 변화), **새로움**(재공시·종결·사본은 탈락), **정례성**(행정·거버넌스는 탈락), **방향 전환**(결정·계약·소송 결과는 통과 쪽), **정보 가치**(월간 실적은 ±10%), **놓침 비용 우선**, **계산은 다음 단계의 몫**.
- 현재 시스템의 규칙: 공시명 규칙 필터(`dart_rules.py`) → 본문 기반 판단(`judge_rules.md`: 30억 원·1%·정례성·주식수 변동은 KIND).

### 2-3. 사용자 판정에서 읽은 선호 (1차 검토 메모)

- 금액이 비공개인 **의무 공시 계약**(경영상 비밀유지, 방산 등)은 중요 → `PASS_CHECK`.
- **법원 판결은 중요**(효성 대법원 판결 → `PASS`).
- **전망(Forward Year)·기업가치제고계획 같은 정보 전달성 공시**는 변화가 크지 않으면 `DROP` 선호 — 아직 규칙화하지 않았다.
- **리츠는 정말 중요한 것이 아니면 무시**, **단순 기간 만료 신탁 해지**는 무시.
- 정정 공시는 **너무 자주 알리면 문제** → 증감률 1% 이상 조건을 추가.

## 3. 파이프라인과 Jev의 위치

```
OpenDART 전체 공시 (하루 약 620건)
  └ 종목 리스트(코스피 290)                     약 100건/일
      └ 공시명 규칙 필터 (분쟁 리스트 예외 적용)     약 83% 종료
          └ review 약 15~17건/일
              └ 자회사 중복 제거(dart_subsidiary)
                  └ ★ Jev 분류자 (질문 v2b, 본문 포함, 영어) ★
                        Noul ≥0.5 → 진행 (PASS / PASS_CHECK)  → 에이전트 심화 분석
                        0.2 ≤ Noul < 0.5 → HOLD (진행 + 검수 표시, 하루 약 2.8건)
                        Noul < 0.2 → DROP
```

| 단계 | 담당 |
|---|---|
| 억 원 환산, 정정 증감 계산, 분쟁 리스트·금융회사 맥락 입력 | 코드 |
| 의미 판단 (질문 묶음에 대한 확률) | Jev |
| 임계값, 라벨 결정, 검수 표시 | 코드 |

## 5. 결과

### 5-1. 1차 검증 요약 (v1을 새 주간에 그대로 적용, 이전 라벨 기준)

재현율은 유지되고(Noul ≥0.5: 개발 96% → 검증 94%) 정밀도는 90% → 65%로 떨어졌다. 떨어진 원인은 자회사 사본·부속 공시(11건), 정례 성격 공시(11건), 풍문 재공시(5건) 등 **규칙 해석·맥락 문제**였고, 이것이 이번 정책 질문의 근거가 되었다.

### 5-2. 사람 판정 반영 결과

- 126행 모두 판정이 있었다. **명시적 판정 54건**(Claude 라벨을 바꾼 33건 + 메모를 단 21건)을 정답에 확정했고, 값과 메모가 모두 기본값 그대로인 72건은 확정으로 보지 않았다.
- 바뀐 33건의 전환: `PASS→PASS_CHECK` 7, `PASS_CHECK→DROP` 7, `DROP→PASS` 6, `HOLD→DROP` 4, `PASS→DROP` 4, `DROP→PASS_CHECK` 3, `PASS→HOLD` 1, `HOLD→PASS` 1. **`HOLD` 6건 중 4건이 `DROP`, 1건이 `PASS`로 정리**됐고, `PASS_CHECK` 7건이 `DROP`으로 내려갔다(정정 공시 6건 + 오리온 월간 실적 1건).
- 정책 계층이 18건을 바꿨다(Q3 풍문 9, Q2 연장·금융 4, Q8 3, Q6 2). 그중 11건은 사람이 기본값으로 둔 행과 충돌해 정책이 이겼다.
- 파일 형식 문제가 있었다: 엑셀이 접수번호를 과학 표기로 바꿔 놓았고(원본과 행 대조로 복구), 인코딩은 CP949·구분자는 탭이었다. 2차 큐에는 문자형 `행ID`를 넣어 복구가 확실하도록 했다.

### 5-3. v1 vs v2 vs v2b (운영 시나리오, 181건, 정답 진행 106건)

| 설정 | Noul ≥0.2 | Noul ≥0.3 | Noul ≥0.5 |
|---|---|---|---|
| v1 TD-en | 100% (0/106) / 65% / 163건 | 98% (2/106) / 68% / 153건 | 93% (7/106) / 72% / 137건 |
| v2 TD-en | 97% (3/106) / 75% / 138건 | 90% (11/106) / 80% / 119건 | 84% (17/106) / 88% / 101건 |
| **v2b TD-en** | **98% (2/106) / 74% / 140건** | 93% (7/106) / 79% / 126건 | **89% (12/106) / 86% / 109건** |
| v2b TD-ko | 94% (6/106) / 78% / 129건 | 91% (10/106) / 83% / 115건 | 81% (20/106) / 91% / 95건 |

표기: 재현율 (놓침/정답 진행) / 정밀도 / 진행시킨 건수.

- v2b가 가장 균형이 좋다. v2의 약점(Q1 예외 누락)을 보완하자 Noul ≥0.5 재현율이 84% → 89%로 올랐다.
- **영어 질문이 한국어보다 낫다**(≥0.5 재현율 89 vs 81, ≥0.2에서 98 vs 94).
- 구간별 재현율(v2b TD-en, Noul ≥0.2): 개발 98% (1/41) · 검증 9/1~9/4 97% (1/39) · 검증 9/30~10/1 100% (0/26).

### 5-4. 제안 운영 구성의 분포 (v2b TD-en, 11거래일)

| 구간 | 건수 | 그중 정답 진행 | 비고 |

### 5-5. 규칙 필터 조정 (Q12)

- **분쟁 리스트 예외**: 주주총회 관련·의결권 대리행사 권유·기준일 설정·독립이사 공시를 분쟁 리스트 회사에서는 제외하지 않는다. 근거: 규칙 필터가 닫은 382건 중 진행 라벨이 붙은 것은 **고려아연 임시주총 결과 1건뿐**이었다.
- **제외 유형 추가**: 주주명부폐쇄·기준일(사람 판정 7/7 `DROP`), 독립이사 선임·퇴임(6/6), 지속가능경영보고서(3/3). 앞의 두 유형은 분쟁 리스트 예외.
- 시뮬레이션: 새로 제외되는 판정 대상 14건, **진행 라벨 0건**. 개발 주간 review 85 → 78건. 풍문·조회공시는 제외로 올리지 않았다(비용 이점이 없고 Jev가 정책을 따른다).
- 구현: `dart_rules.classify(report_nm, corp_name=None)` — 기존 호출은 그대로 동작. 12개 단위 시험 통과.

| 순서 | 규칙 필터(분쟁 리스트 예외) → 자회사 중복 제거 → Jev |
| 질문·입력 | **v2b**, 본문 포함(요약 6,000자), 영어 질문, 원 단위 억 환산, 분쟁 리스트·금융회사 맥락 전달 |
| 진행 판정 | Noul ≥0.5 → 진행, 0.2~0.5 → `HOLD`(진행 + 검수 표시), <0.2 → `DROP` |
| 4단계 라벨 | Choice의 선택을 `PASS`/`PASS_CHECK` 구분에 사용(`HOLD`는 확률로 결정) |
| 단독 사용 금지 | Score 단독, 원자 Noul 조합 단독 |

이 운영안은 **개발·검증 3개 구간에서의 일치도**일 뿐이며, 사람 라벨 확정과 새 주간 검증 전에는 잠정이다.

## 7. 한계

- **라벨이 독립적이지 않다**: 정책 계층(18건)은 v2와 같은 정책에서 나왔고, 사람 판정은 어려운 건 위주(36건)다.
- **사람이 기본값을 그대로 둔 72행**이 사람 확정인지 알 수 없어 확정으로 보지 않았다. 이 중 풍문 해명 `PASS` 등은 Q3과 충돌한다.
- **가정값 두 개**: 1,000억 원(Q1), 200억 원·1%(Q6).
- **표본이 작다**: 진행 106건, 놓침 2건. 새 구간(9/14~9/29)은 정답이 없다.
- **정정 공시**: 정책 변경 후 정정 `PASS_CHECK`가 3건뿐이라 평가 표본이 사실상 없다.
- 요약(6,000자)이 매우 긴 표를 완전히 담지는 못한다.
