# Jev 공시 분류자 — 실험 설계안과 1차(일주일) 결과

> 대상: 2026-09-07~09-11 코스피 290 종목 공시. 기준 문서: `공시판단_기본원칙.md` (v0.2).
> 모델: `jev-1.13.0` 고정(별칭 `jev-latest` 대신 버전 ID를 써서 재현성 확보). 요청당 비용 약 $0.0001(입력 약 2천 토큰) — 비용은 설계 변수가 아니다.
> **정답 라벨은 Claude가 위임받아 매긴 `claude_v0`이며 사람 검수 전이다.** 아래 수치는 "정답셋 대비 일치도"이지 정확도의 증명이 아니다.

## 1. 역할과 라벨

Jev는 **분류자**다. 공시 1건을 받아 다음 4가지 중 하나로 보낸다.

| 라벨 | 의미 | 다음 동작 |
|---|---|---|
| `PASS` 통과 | 본문만으로 중요 판단이 선다 | 다음 단계 |
| `PASS_CHECK` 통과·확인 | 진행 쪽이나 계산(비율·전년 동월비) 또는 정정 전후 대조 필요 | 다음 단계 + 확인 사항 표시 |
| `HOLD` 보류 | 규칙 충돌·해석이 갈림 → 사람 검토 | 검수 큐 |
| `DROP` 탈락 | 중요하지 않음 | 종료 |

비교 기준 계산(자기자본·매출 대비 비율 등)은 Jev가 단순 통과시키지 않고 `PASS_CHECK`로 표시해 다음 단계의 에이전트가 맡는다.

## 2. 실험 설계안

### 2-1. 시험할 요인

| 요인 | 수준 | 이유 |
|---|---|---|
| 질문 유형 | Noul(한 덩어리 "넘길까?") · Choice(4단계 라벨) · Score(중요도 0~4) · **원자 Noul 8~10개 + 코드 조합** · 앙상블(OR / 2-of-3) | 사용자 구상: 세 유형을 모두 시험한 뒤 종합 |
| 입력 | T(제목+회사명) · TD(+본문 요약, 정정이면 정정 전·후 표와 증감) | 제목만으로 얼마나 가려지는지 |
| 질문 언어 | 한국어 · 영어 (state는 한국어 그대로) | 문서가 "CJK는 영어보다 정확도가 낮을 수 있으니 직접 시험"을 권고 |
| 전처리 | v0(원문 그대로) · v1(원 단위 숫자에 `(약 N억 원)` 병기, 정정 증감 계산) | 결정적 계산은 코드가 맡는다는 원칙 |
| 규칙 필터 | 선행(기본값) · 제거(Jev만) | 사용자 방침: 기본은 선행, 제거는 시험으로만 |
| 정정 공시 | 시험으로만 평가(운영 파이프라인에는 적용하지 않음) | 사용자 결정 |

### 2-2. 지표

- **재현율** — 진행해야 할 공시를 진행시킨 비율. **1순위**(놓침은 복구 경로가 없음).
- **정밀도** — 진행시킨 것 중 진행이 맞는 비율. 다음 단계 에이전트 비용(공시당 약 2.7만 토큰)과 직결.
- **HOLD 처리**: (a) 진행으로 간주 (b) 채점 제외 두 가지를 병기.
- **임계값 선택 규칙**: 재현율 95% 이상이 되는 가장 높은 임계값을 고른다. 임계값은 코드에서 정하므로 요청을 다시 보내지 않고 저장한 확률로 재계산한다.
- **보조 지표**: 4단계 혼동행렬, Jev가 놓친 건·불필요하게 통과시킨 건 목록, 재실행 일관성.

### 2-3. 절차와 규칙

1. **정답셋 고정** — `cases/cases_v0.json` (판정 82 + 정정 35 + 규칙 제외 382). 라벨·근거·`was_borderline`을 함께 저장.
2. **개발 표본과 검증 표본 분리** — 이번 주(9/7~9/11)는 개발 표본이다. 질문·전처리를 고친 뒤에는 **반드시 새 주간으로 검증**한다(같은 표본에서 고친 개선폭은 낙관적).
3. **버전 관리** — 질문은 `questions.py`의 `v0`, `v1` …로 보존하고, 실험은 `runs/<이름>/raw_<설정>.jsonl`(원응답 전체)로 남긴다. 결과 비교는 `compare_runs.py`.
4. **수정 원칙** — 질문 수정은 개별 사례가 아니라 **`공시판단_기본원칙.md`에 적힌 원칙**을 근거로만 한다. 수정마다 어느 원칙인지 기록한다.
5. **일관성 점검** — 같은 설정을 두 번 돌려 판정이 뒤바뀌는 비율을 본다. 이 비율보다 작은 차이는 개선으로 읽지 않는다.
6. **라벨 검수** — 사용자가 `HOLD`·`was_borderline` 건부터 확인하고, 바뀐 라벨로 재채점한다(채점은 저장된 응답으로 즉시 가능).

### 2-4. 다음 실험 후보 (우선순위 순)

1. **새 주간 검증**: v1 질문을 그대로 9/1~9/4 또는 9/30~10/1(이미 `trial_case`에 판정이 있음)에 적용 — 일반화 여부. *(사용자 승인됨, 이번 결과 확인 후 진행)*
2. **임계값 보정**: 새 주간의 확률로 재현율 95% 지점 확인.
3. **회사 맥락 필드**: 경영권 분쟁 중 등 상황을 코드가 `company_context`로 넘기는 방식(§3 고려아연 사례).
4. **정정 사유 반영**: 정정 사유가 "오류 정정"이면 증감이 커도 탈락 쪽으로(§3 LS 사례).
5. **Choice 보강**: 라벨별 설명을 객체형(`what`/`not_for`/`examples`)으로 구조화, `HOLD`가 거의 안 나오는 문제 개선.
6. **긴 본문**: digest(1,500자) 대신 핵심 절만 발췌해 넣는 방식과 비교(32k 토큰 한도 내).

## 3. 1차 실행 결과 (개발 표본)

실행: v0 4개 설정(T/TD × ko/en) + 규칙 제외 382건(제목만), v1 3개 설정, 재실행 1회. 총 약 1,700회 호출, 오류 0.
원본: `runs/w0907_v0/`, `runs/w0907_v1/`, `runs/w0907_v1_rerun/`, 표는 `runs/comparison.md`, 설정별 상세는 각 `report.md`.

### 3-1. 판정 82건 — 재현율 / 정밀도 (HOLD는 진행으로 간주)

| 방식 | v0 T-en | v0 TD-en | v0 TD-ko | v1 TD-en | v1 TD-ko |
|---|---|---|---|---|---|
| Noul ≥0.5 | 82 / 84 | 89 / 91 | 79 / 94 | **96 / 90** | 84 / 94 |
| Noul ≥0.3 | 100 / 76 | 98 / 79 | 89 / 84 | 98 / 79 | 95 / 87 |
| Choice | 89 / 85 | 88 / 85 | 84 / 86 | 84 / 89 | 86 / 92 |
| Score ≥2.0 | 47 / 82 | 79 / 92 | 75 / 96 | 81 / 94 | 74 / 95 |
| 앙상블 OR(Noul·Choice·Score) | 98 / 81 | 100 / 84 | 95 / 87 | 98 / 86 | 93 / 91 |
| 원자 Noul 조합 | 91 / 78 | 82 / 77 | 75 / 86 | 91 / 78 | 88 / 88 |

### 3-2. 정정 공시 — 정형 서류 정정 11건을 유형 규칙으로 먼저 제외한 23건

| 방식 | v0 TD-en | v1 T-en | v1 TD-en | v1 TD-ko |
|---|---|---|---|---|
| Noul ≥0.5 | 100 / 59 | 30 / 23 | 50 / 71 | 50 / 71 |
| Noul ≥0.3 | 100 / 50 | 100 / 45 | **100 / 83** | 70 / 78 |
| 앙상블 OR | 100 / 53 | 100 / 45 | 100 / 67 | 100 / 62 |

### 3-3. 해석

1. **판정 대상에서는 Jev 단독으로도 쓸 만하다.** v1·영문 질문·본문 포함에서 Noul ≥0.5가 재현율 96%, 정밀도 90%다. 놓친 2건은 오리온(월간 실적, 국가별 합산 계산 필요)과 아모레퍼시픽 전망(0.40)이고, 불필요 통과 6건은 아래 4번에서 본다. 세 유형을 합친 앙상블 OR은 재현율 98%, 정밀도 86%다. **재현율 우선 정책에서는 앙상블 OR이 가장 안정적**이다(v0·v1, 모든 설정에서 93~100%).
2. **제목만으로도 재현율은 높다.** T-en Noul ≥0.3이 재현율 100%, 정밀도 76%다. 금액형 공시(단일판매·채무보증 등)는 제목이 거의 결정하기 때문이다. 본문은 월간 실적·풍문 해명·정정처럼 제목이 같고 내용이 갈리는 유형에서 정밀도를 올려 준다.
3. **영어 질문이 한국어 질문보다 대체로 낫다**(Noul ≥0.5 재현율 v0 89 vs 79, v1 96 vs 84). 문서의 경고와 일치한다. 한국어 질문은 임계값을 낮추면 보완된다(≥0.3에서 95%). 단일 주간이므로 확정이 아니라 가설이다.
4. **남은 오류는 "Jev가 알 수 없는 맥락"이나 "계산"이 필요한 유형이다.**
   - v1 TD-en의 불필요 통과 6건: 조회공시 미확정 재공시(SK하이닉스 0.86), 자회사 사본(에이피알 0.64), 확정으로 종결된 풍문 해명(태광산업 0.63), 소액 임원 거래(한미반도체 7억 0.54), 불성실공시법인 지정 2건(0.51~0.52, 경계). 앞의 두 건은 **이미 공시된 사안인지**를 본문만으로는 알 수 없다 → 직전 공시 이력(재공시 여부)이나 자회사 쌍둥이 탐지를 코드가 알려주는 방식이 필요하다.
   - 놓친 건: 오리온은 국가별 실적을 합산해야 ±10% 여부가 나오는 **계산형**이어서 라벨이 `PASS_CHECK`다. 이런 건은 Jev의 진행 확률이 낮아도 `needs_comparison` 원자 질문으로 따로 잡는 설계가 맞다.
   - **한국어 질문에서는 고려아연 독립이사 개편(경영권 분쟁이라는 회사 상황이 본문에 없음)이 0.39로 놓친다**(영문은 0.58). 회사 맥락 필드(§2-4-3)가 필요한 유형이다.
   - 자사주 신탁 해지·정례 자금운용처럼 금액은 크지만 정례인 유형은 **정답 라벨 자체가 갈리는 영역**이다(시프트업·SK리츠·대신증권은 `HOLD`).
5. **정정 공시는 증감을 코드가 계산해 넘기면 분리된다.** 수치가 있는 정정(신한지주 +48%, SK디스커버리 +26%, DL이앤씨 +7.2%, HJ중공업 +4.3% 등)은 Noul 0.80~0.96으로 잡힌다. 정형 서류 정정을 유형 규칙으로 먼저 거르고 Noul ≥0.3을 쓰면 재현율 100%, 정밀도 83%다(23건 중 10건이 진행 대상). 남은 오탐은 자회사 사본(DL)과 **정정 사유가 "오류 정정"인 건**(LS 교환사채: 단위 오기로 증감이 -99.9%로 계산됨)이다. 증감이 없는 후속 사건(SKIET 거래 종결, HD현대 소송 제기, 삼성바이오 기간 연장)은 확률이 0.33~0.44로 낮아 임계값 0.3이 필요하다.
6. **Jev는 규칙 필터를 대체하지 못한다 — 선행이 맞다.** 규칙 필터가 닫은 382건을 제목만으로 Jev에 넣으면 영문 질문 Noul ≥0.5에서 108건(28%)이 진행으로 나온다. 특히 `최대주주등소유주식변동신고서` 34/34, `대량보유상황보고서` 28/28이 전부 진행이었다. 지분 변동은 이 프로젝트에서 KIND 크롤링으로 따로 처리하는 대상이므로, Jev에 맡기면 안 된다는 방침을 뒷받침한다.
7. **Choice의 `HOLD`는 거의 나오지 않는다.** 판정+정정 117건에서 `HOLD` 선택은 v0 제목만 0건(ko·en), v0 본문 포함 ko 1건·en 8건, v1 본문 포함 ko 0건·en 9건이다. 정답 `HOLD` 6건 중 `HOLD`로 보낸 것은 v1 TD-en에서 3건, 나머지 설정에서는 0~2건이다. 사람 검토 큐를 Jev의 `HOLD` 선택에만 의존하기는 어렵다. 확률이 경계(0.3~0.7)에 걸린 건을 코드가 검수 큐로 보내는 방식을 다음에 시험한다(`composite_u`는 판정 82건에서는 차이가 없었다).
8. **원자 Noul 조합은 본문 포함 설정에서 단순 Noul보다 낮다**(v1 TD-en 재현율 91 vs 96). 제목만 입력(v1 T-en)에서는 95로 오히려 높았다. 조합 규칙(코드)이 단순해서 생긴 손실로 보이며, 특성별 확률은 저장돼 있으므로 규칙을 바꿔 즉시 재채점할 수 있다. 조합의 장점은 판정 이유가 보인다는 점이다.
9. **Score는 단독으로는 부적합하다.** 임계값 2.0에서 제목만 입력이면 재현율 47%, 본문을 넣어야 74~81%다. 보조 지표(정렬·강도)로 쓰는 편이 낫다.

### 3-4. 신뢰도와 한계

- **같은 설정 재실행**: Noul 평균 차이 0.013(최대 0.08), 0.5 기준 판정이 뒤바뀐 건 2/117, Choice 선택이 뒤바뀐 건 5/117. 따라서 **1~2건 차이는 잡음**이다. v0→v1 개선(96 vs 89)은 이 경계에 가깝다.
- **표본**: 진행 대상 57건, 정정 중 진행 대상 10건. 신뢰구간이 넓다.
- **v1은 같은 표본에서 고쳤다.** 일반화는 새 주간 검증 전에는 확인되지 않았다.
- **라벨**: Claude 위임 판정이다. 규칙 필터를 통과한 판정 대상은 이전 판정(같은 Claude)을 4단계로 재라벨한 것이어서 독립 정답이 아니다.
- **임상 예외(P4)**는 v0·v1 질문에 이미 들어 있고, 셀트리온 임상계획 변경 승인 2건은 v1에서 Noul 0.92~0.93으로 통과했다.
